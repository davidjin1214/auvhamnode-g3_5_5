## 2. 核心方法论：证据先行 + 方案先行 + 作者/审稿分离 + 多轮迭代收敛

### 2.1 阶段拆分严格，一个会话只做一种事

典型闭环：

```
证据总账 → 方案讨论（勿动笔）→ 方案落档（自包含 md）→ 独立审查方案
        → 执行落稿 → 编译核验 → 独立复审 → 逐项讨论定夺 → 下一版
```

- §1.7 走了 v1→v10 十个版本；§1.8 走了完整三步制
  （Step 1 审方案 / Step 2 导数据 / Step 3 动主稿）。
- 会话类型学（八类）：上下文装载 / 证据总账 / 方案讨论 / 审查（只审不改）/
  修订执行 / 落稿收尾（编译+核验+commit）/ 图表（方案→绘制两段式）/ 状态盘点。

### 2.2 作者与审稿分离是铁律

- 审查型 prompt：「本轮只审不改」「你是审稿人不是作者，不要替前几稿辩护」。
- 修订型 prompt：「你是协作修订者，但不为既有措辞无条件辩护，
  也不无条件照搬复审清单」。
- 动稿后必须派独立 agent 二次核验（科学内容/数值可追溯、红线无损、
  交叉引用闭环、术语一致、语域达标）。

### 2.3 决策权始终留在用户手里

- 方案型 prompt 必须输出「待我拍板的开放问题」清单。
- 执行型 prompt：「缺数字标记出来让我确认，不要臆造」。
- 图表任务：方案讨论留在主线程与用户来回，确认后才交子 agent。

### 2.4 事实底座前置、防幻觉措施具体

- 每条 prompt 都有「必读（按顺序）」清单，注明每个文件是什么、读哪部分。
- 数字必须可追溯：`analysis/oc_data_catalog/` 的 `canonical_rollout_*` 表 +
  `evidence_status` 闸门（stale 运行不得进入主排序）。
- 「不得虚构未做过的实验」并给出具体例子（如步长/求解器阶数敏感性
  §1.7 已声明未考察，后文不得声称做过）。
- 图表审查：「务必亲自看渲染出的 PNG 图像，不要只读脚本臆测」。

### 2.5 红线全文重复贴入，且标注属性

五条设计红线每次全文贴入 prompt，并明确标注
**「属有意为之，切勿当作错误去修正」**——这是防止 AI 把刻意设计当 bug
改掉的关键一句。红线内容以 `AGENTS.md`（Paper Boundaries）与
`paper/README.md` 为权威来源，此处仅登记条目名：

1. 端口哈密顿语义仅限开放式六自由度机械核心；τθ ≠ G(q)u。
2. 海流双口径：模型契约层分段常值 / 数据生成层连续缓变 OU 外场，各自准确不可混淆。
3. 普通 ODE 求解器不严格保持 SO(3)/能量；不得出现「严格保群/保结构积分」类过度声明。
4. 初值扰动 = 鲁棒性正则，非导航后验；噪声预算物理接地、与数据集无关。
5. §1.7 不报告性能数值/排名（数值与排名属 §1.8，且一律条件化，不外推为普遍定理）。

## 3. 可复用的八段式 prompt 模板

```markdown
# 任务：<动词 + 精确范围（节号/图号）+ 本轮性质（讨论方案/只审/执行）>

## 角色
多重身份：<领域专家（列出具体子领域）> + 严格的中文博士学位论文审稿专家
+ 资深中文学术编辑。
（图表任务追加：顶刊级科研可视化专家。）
基调：严格校准、不夸大不漏报；结论以「亲自读到的正文 / 编译出的 PDF /
核对过的数据」为准，不凭脑补下判断；欢迎大胆质疑既有结构与取舍。
全程中文、关键信息表格化。

## 环境与路径
- 仓库根：<绝对路径>
- 主稿：<路径>（章节定位提示）
- 编译：xelatex；`export PATH="/Library/TeX/texbin:$PATH"` 后
  `latexmk -xelatex -interaction=nonstopmode <主稿>`
- conda 环境 mytorch1；`conda run` 在本机沙箱常被拒——直接用绝对路径
  `/opt/homebrew/Caskroom/miniforge/base/envs/mytorch1/bin/python <脚本>`

## 必读（按顺序，勿跳过）
每个文件一行：<路径> —— <它是什么、本轮读哪部分、权威级别>
定位约定：按 \section/\subsection/\label 标题定位，勿依赖固定行号（行号会漂移）。

## 背景与当前状态（勿重做的部分）
- 前序会话已完成什么（含 commit 号）；哪些草稿版本已作废、仅供了解脉络勿审。
- 术语已统一到什么口径（见 §4 对照表）。

## 红线与证据闸门
- 五条设计红线全文贴入 + 「属有意为之，切勿当作错误去修正」。
- 证据闸门：每个数值/排名可追溯到证据目录并核 evidence_status；
  缺数字标记待我确认，不得臆造；不得虚构未做过的实验（举具体例子）。
- 语域要求：正式中文论文非备忘录/实验报告；禁源码变量名/函数名/数据集
  文件名/脚本名/配置键入正文；模型用规范中文名（代号仅限表格内）；
  不反复强调随机种子（可靠性记账下沉到表注或一句方法回指）。

## 工作流程（强制）
1. 第一步只做 X（方案讨论/独立审查），待我确认后再 Y（动稿）。
2. 动稿后自行编译核验 + 派独立 agent 二次核验，把核验结论回报。
3. 审查输出严重度四级校准：CRITICAL（须改）/ HIGH（应改）/ MEDIUM（建议）
   / LOW（可选），勿夸大；每条问题给精确定位（节号+原文摘录）
   + 可执行修改建议（能给改写示例更佳）。
4. 列出「待我拍板的开放问题」。

## 交付物
- 报告存档：paper/drafts/<主题>_<YYYYMMDD>_zh.md，必含结构逐项列出
  （总体评价 / 节×严重度问题清单表 / 专项结论 / 排好优先级的修改清单）。
- 提交策略：非 main 分支提交、中文 commit message、docs: 前缀、
  本地不主动推送，等我指示。
```

### 3.1 图表任务的两段式变体

1. **方案段（主线程）**：只讨论 2–3 个版面/叙事构图方案（各配 ASCII 草图
   + 优缺点 + 推荐及理由 + 接入位置建议与既有图分工），不写任何绘图代码。
2. **绘制段（确认后）**：调用 `nature-figure` 子 agent，把「已确认构图方案
   + 红线清单 + 风格与产出约定 + 既有 `figures/make_*.py` 风格基线」作为
   完整输入传入；产出投稿级 PDF/PNG/SVG + 可复现脚本
   （宽度 ≤138mm、色盲安全配色、图内英文标签+中文 caption、
   公式锚点放 caption 用 \eqref 指向主稿）。
3. **审查段**：审图必须亲自查看渲染 PNG，不得只读脚本推断。

## 5. 收敛判据（迭代循环的退出条件）

已在 §1.7/§1.8 实践中成型，后续章节可直接宣告采用，省去重新协商：

   术语一致 / 语域达标 / 无代码腔与种子腔）。

## 6. 经验教训与改进建议

1. **大任务先落档方案再执行。** 多个会话是同一 prompt 的 fork
   （上下文耗尽重开）。§1.8 的解法：先把完整实施方案自包含落档为 md
   （「越详尽越好、数据标注可追溯来源」），任何一次重开都能冷启动。
   这是对抗长任务上下文损耗的最有效手段。
2. **红线段全贴优于回指。** 红线已在 CLAUDE.md/AGENTS.md 有登记，
   但历次 prompt 仍每次全文贴入——这个冗余值得保留，实践表明比
   「见 AGENTS.md」更稳。
3. **行号会漂移。** 一律按 `\section/\label` 定位；prompt 中给行号只作
   粗定位参考并注明「动手前重新 grep 定位」。
4. **本机环境坑位写进 prompt。** `conda run -n mytorch1` 在沙箱常被拒
   → 直接用绝对路径 python；xelatex 需先 `export PATH="/Library/TeX/texbin:$PATH"`。
   每次贴入可避免执行段反复试错。
5. **审查报告落档命名约定**：`paper/drafts/<主题>_<YYYYMMDD>_zh.md`，
   草稿片段 `section_X_Y_rewrite_draft_vN_zh.tex`；历史版本作废后在下轮
   prompt 中显式声明「勿审」。
6. **跨项目复用**：VIN 论文（`new_cvin/vin_ocean_2`）已用同构模板，
   后续直接套用本 playbook §3 骨架，替换环境段与红线段即可。
