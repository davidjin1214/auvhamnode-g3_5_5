## A. 高水平 DL / Neural ODE 实验结果节的写作惯例（作为组织依据）
- **设置紧凑、caveat 下沉**：开头用 1–2 句点明本节要回答的问题，再以最简设置（数据 / 基线 / 指标 / 协议各一句、细节指向方法节或附录）带过。**完成率怎么算、发散怎么判、哪些 run 被排除、为何分层治理，全部下沉到图表注、脚注或方法回指**，不占正文开篇。
- **以研究问题 / 假设组织**：结果作为对若干结构假设的逐条回答（几何是否必要？能量核心是否主导精度？非保守力分解的边际作用？训练协议是否敏感？），轻量引导、不必强行 RQ 编号。
- **主结果先行**：最强对照与核心结论用主表 / 主图打头。
- **消融给完整阶梯**：remove-one 设计，量化每个结构成分的边际作用；干净集内的消融阶梯要完整呈现，更广模型的受限消融分级单列。
- **鲁棒性 / 压力测试**：随评估扰动递增、随训练协议变化，诚实展示优势在哪里成立、在哪里收窄。
- **诊断 / 机理**：内部物理探针（能量、SO(3) 正交性）解释*为什么*，与任务误差分开。
- **图、表、文分工**：
  - **图承载趋势与格式塔**：训练 / 验证收敛曲线（收敛性与训练稳定性，黑箱发散本身即证据）、误差随预测时域增长（neural ODE 长期外推的核心图，体现短时域接近、长时域分化）、扰动梯度折线（排序收敛）、误差分布（箱线 / 小提琴，中位数 vs 尾部 P95）、内部诊断；
  - **表承载精确数字**；**正文承载论点与解释**，不复述表里的数字。
- **多阶段叙事**：让结果读起来像"一个实验回答一个问题、层层递进"，而不是一次性甩出所有数字。
- **负面结果诚实**：报告不占优处与失效模式，增强可信度。
- **claim 条件化但不防御**：见 §E。

## D. 沿用全章五条设计红线（有意为之，核查一致即可，不得当作错误"修正"，更不得在新内容里破坏）
1. 端口哈密顿语义仅限开放式六自由度机械核心；τθ ≠ G(q)u；完整航行器–执行器–环境系统是受控开放系统，不构成闭合端口哈密顿系统。

3. 普通 ODE 求解器**不严格**保持 SO(3) / 能量；不得出现"严格保群 / 严格保结构积分"之类过度声明（正交性误差小但非零，作诊断量）。
